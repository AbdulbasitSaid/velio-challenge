## 1. Problem statement

Zainab and Kofi mostly arrive on phones with weak connections (PRD personas, NFR Performance). The PRD requires a Flutter app that opens a link or a typed code, shows the invite with live spots, claims in one tap, keeps the last viewed activity for offline viewing, and confirms with haptics (M1–M3), plus My plans (L2) and native maps (A5, MAP-D3). There is no mobile code and no Dart client.

## 2. Context and current behavior

- [Verified, repository] No `apps/mobile`. `packages/contracts/openapi.json` is generated from the Zod schemas (`bun run contracts:openapi`).
- [Verified, `apps/api/src/modules/identity/`] Sessions and claims return the token in the body for `X-Client: mobile`; the API reads `Authorization: Bearer` before the cookie. `X-Device-Id` is accepted.

- [Verified, UI design Flutter artboards] Code entry is the app's home with a "My plans" entry; the Plan has "Invite a friend"; G4 offers Apple Maps or Google Maps on iOS; the returning-guest claim reads "Claiming as {Name} / {masked contact} · saved on this phone / Not you?"; X4 includes "This link needs a newer version of the app".
- [Verified, MVP plan §5] Flutter 3, Riverpod, go_router, dio, `app_links`, `web_socket_channel`, `shared_preferences` or Hive, `HapticFeedback`; Dart client generated by `openapi-generator` (dart-dio).

## 3. Desired outcome

An iOS and Android app in which a guest types a code or taps a link, sees the invite with live spots and a native map, claims in one tap (two fields the first time, none after), feels a haptic and sees "You're in" with the booking reference and directions, can open the Plan and invite their own friends, and finds every Plan in My plans, including offline from cache. Links open the app when installed on Android (verified App Links); on iOS they open the web page and the app is reached by code entry (§12 Q1).

### 4.2 Dependencies [Proposal]

Latest stable of each at implementation, pinned exactly in `pubspec.yaml` and `pubspec.lock` (CLAUDE.md): `flutter_riverpod`, `go_router`, `dio`, `app_links`, `web_socket_channel`, `shared_preferences` (offline cache as JSON: two small documents, no need for Hive), `flutter_secure_storage` (token, device ID), `google_maps_flutter`, `url_launcher` (directions), `share_plus` (invites, "Tell {Inviter}"), `connectivity_plus` (offline hint; requests remain the truth), `intl`, `timezone` (show times in the activity's IANA zone), `uuid`. Haptics use `HapticFeedback` from the SDK. Fonts are bundled assets (S5 §4.3).

### 4.3 Dart API client [Proposal]

- Generated with `openapi-generator` `dart-dio` from `packages/contracts/openapi.json`, run through the official Docker image (pinned by digest) so no local Java setup is needed: `bun run contracts:dart`.
- Output is committed in `packages/api-client-dart/` with its generated serializers, so Flutter builds don't need Docker.
- CI regenerates and fails on a diff, so the three codebases can't drift (MVP plan §8).
- If the generator's output for the Zod-derived schemas is unusable (for example, discriminated unions), fall back to hand-written models for those types only, recorded in the change log [Assumption: checked at T2].

### 4.4 Identity [Proposal]

- **Device ID:** a UUID created on first launch, kept in secure storage, sent as `X-Device-Id` on every request.
- **Session:** `POST /api/sessions` (X1) and claims with `X-Client: mobile`; the returned token goes to secure storage and is sent as `Authorization: Bearer`. A `401` clears it.
- **Returning guest:** at sign-in or first claim, the app keeps the display name and a masked contact (`+44 •••• ••12 34`, `z••••@gmail.com`) locally for "Claiming as … saved on this phone". The raw contact is never stored (PRD Privacy). "Not you?" signs out (`DELETE /api/sessions/current`) and clears the local profile.

- **Sold out on claim** gets a distinct haptic (`HapticFeedback.heavyImpact`) as it lands on G5 (PRD M3).

### 4.6 Deep links [Proposal; Q1 and Q2 decided 2026-11-04]

- **Android App Links:** intent filter with `android:autoVerify="true"` for `https://depimls1pcvv4.cloudfront.net/i/…`; `assetlinks.json` (S6) lists the package and the signing SHA-256 of the build used for the demo (the local debug keystore, since the app isn't distributed).
- **iOS Universal Links:** out of scope. There is no Apple Developer Program team (decided 2026-11-04), so no Associated Domains entitlement; iOS runs on the simulator, `/i/<code>` links open the web page, and the app is reached through code entry.
- `app_links` delivers both the cold-start link and later links to the router, which normalises the code and opens `/i/:code`. Paths the app doesn't know go to X4 "needs a newer version" with "Open in the browser instead".
- No custom URL scheme: links stay `https`, so they work everywhere, and the web page is the fallback (PRD M1).

### 4.7 Realtime [Proposal]

Same six rules as the web client (S5 §4.7), with `platform=ios|android`. The socket closes when the app goes to the background and reconnects with `resume=1` (subscribe, then refetch the snapshot) on resume. Spots changes are announced with `SemanticsService.announce`, politely, at most once per 5 s (UX NFR-003).

### 4.8 Offline (PRD M2) [Proposal]

- Cache the **last viewed invite** (the full `InviteView` plus the fetch time) and the **last My plans list**, as JSON in `shared_preferences`, written after each successful fetch. Location fields are included (Maps FR-013).
- Offline (request fails or connectivity reports none): show the cached data with "Last updated {n} min ago", the stale badge, Claim disabled with "Reconnect to claim", and the map area replaced by "Map unavailable offline" with the address (Maps FR-013). Directions still open the maps app.
- **Nothing is queued.** A claim needs a live request; failure shows the retry state (PRD M2, Edge cases).

### 4.9 Maps [Proposal]

- `google_maps_flutter` with one marker and gestures enabled, lite mode on Android list cards if any [Assumption: only detail screens show a map].
- Keys: an Android key restricted to the package and signing SHA-1s, and an iOS key restricted to the bundle ID, both limited to the Maps SDKs (Maps §5.5). They're injected at build time (Gradle manifest placeholder and an iOS xcconfig value from an untracked file or CI secret), so they never enter the public repository [Proposal].
- Without a key, or if the map fails, the address block with directions shows instead (A7).

### 4.10 Configuration and builds [Proposal]

- `--dart-define=API_BASE_URL=…`: production `https://depimls1pcvv4.cloudfront.net`; development `http://10.0.2.2:3001` (Android emulator) or `http://localhost:3001` (iOS simulator). Cleartext HTTP allowed only in debug builds.
- Minimums: the higher of the MVP plan's iOS 15 / Android 8 (API 26) and what Flutter and `google_maps_flutter` require at the pinned versions [Assumption: checked at T1].
- App identifiers: §12 Q3.
- **CI:** a Flutter job in `.github/workflows/ci.yml` pinned to the `.fvmrc` version: `dart format --output=none --set-exit-if-changed`, `flutter analyze`, `flutter test` and the Dart client drift check. No release build or artifact: the app isn't distributed (§12 Q2, decided 2026-11-04).
- **Telemetry:** each request carries a W3C `traceparent` (MVP plan §4.12). Mobile timings (`link_to_render`, `claim_to_confirm`) are S8's.

### 4.11 Tests [Proposal]

- **Unit:** code normalisation and validation; realtime rules against a fake channel (version gate, subscribe-then-fetch, poll every 10 s while disconnected, resync, `plan` refetch, `rendered` once per painted version); offline cache read and write; error-code mapping; idempotency key reuse; avatar colour hash with S5's shared fixtures; masked contact formatting; time-in-zone formatting.
- **Widget:** each screen's designed states, at 360 px and at 390 px with `textScaler` 2.0, asserting no overflow (UI-D5, UI design FR-015).
- **Integration (`integration_test`):** one smoke run against local Compose on an emulator: code entry → invite → claim → You're in → Plan → My plans.
- **Manual:** on a real Android phone or emulator and the iOS simulator: deep links cold and warm, offline in airplane mode, haptics, maps, share sheet into WhatsApp, VoiceOver and TalkBack.

## 5. Architectural considerations

- **Correctness:** the app never decides availability and never queues claims; spots come from snapshots and versioned events.
- **Security:** token and device ID in secure storage (Keychain, Android Keystore-backed); `https` only in release builds; Maps keys restricted and kept out of the repository; deep links accept only `/i/<code>` and validate the code.
- **Privacy:** no raw contact stored; public names only on public screens (PRD Q12); no personal data or codes in telemetry.
- **Performance:** skeletons at once, cached content first on revisits, map widget built only on screens that show it (Maps §11).
- **Accessibility:** semantics labels, 44 px targets, text scaling to 200%, polite announcements, reduced motion respected (`MediaQuery.disableAnimations`).
- **Operations:** no backend change; the app uses the deployed API.

## 9. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Generated Dart client mishandles some schemas | Drift check plus hand-written models for the affected types only (§4.3) |
| No Apple developer account (decided), so no Universal Links | The web page is a full fallback (MVP plan §8); iOS uses code entry; recorded as a limitation |
| `google_maps_flutter` raises the platform minimums or app size | Check at T1; record the minimums; map built only on detail screens |
| Text scaling at 200% overflows | Widget tests at `textScaler` 2.0 for every screen |
| Offline detection is wrong (captive portals) | Treat failed requests as the truth; connectivity only as a hint |
| Token leaks via logs | No request logging in release; interceptors redact `Authorization` |
| Socket kept open in background drains battery | Close on background, resume on foreground |

## 10. Alternatives considered

- **Hand-written Dart models:** no generator, but drift-prone; the MVP plan chose generation.
- **Hive for the cache:** more than two JSON documents need; `shared_preferences` is enough.
- **Static map image in Flutter:** rejected by the owner (MAP-D3).
- **Custom URL scheme:** works without association files but fails silently when the app isn't installed; `https` links fall back to the web page.
- **Bloc instead of Riverpod:** MVP plan alternative; no reason to switch.
